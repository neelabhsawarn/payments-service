# Optional AWS Terraform demo — read before applying

Creates **real billable AWS resources** in your configured account and region. By default the ECS service is **not** deployed because a container image and Kafka endpoint must be supplied first.

## Included

- One VPC, two public subnets, internet gateway/route table, security groups.
- PostgreSQL on Amazon RDS (`db.t4g.micro`, 20 GB gp3, encrypted, not publicly accessible) with **RDS-managed Secrets Manager master password**.
- Amazon ECR private repository, Amazon ECS cluster, optional Fargate task/service with CloudWatch logging and task execution IAM.
- Optional trusted CIDR ingress on port 8080. Default is **no inbound access**. ECS tasks use a public IP for image-pull egress to avoid a NAT gateway for this short demo.

**Important:** Kafka/MSK is NOT provisioned. An operational ECS deployment needs a Kafka broker reachable from the ECS task in this VPC, typically a separately configured MSK/VPC network. `kafka_security_protocol=SSL` is the default; TLS-only support does not replace SASL/IAM auth when your broker requires it. To reach broker in another VPC, you must configure appropriate routing/security groups, and client authentication. Running ECS with no reachable Kafka will not demonstrate the full message flow.

## Steps

1. Install Terraform, Docker and AWS CLI, authenticate using a scoped AWS identity, and configure **AWS Budget alerts**.
2. `cd infra/terraform` and run `terraform init`.
3. Run `terraform plan -out=demo.tfplan` and inspect the resources and costs before applying.
4. `terraform apply demo.tfplan` provisions base resources, including **billable RDS**. The default `deploy_service=false` means Fargate is not yet running.
5. From the repository root, build an image. Get the repository URL from `terraform output -raw ecr_repository_url` in this directory. Authenticate and push it:

```bash
AWS_REGION=eu-west-2
AWS_ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
cd infra/terraform
ECR_REPO="$(terraform output -raw ecr_repository_url)"
aws ecr get-login-password --region "$AWS_REGION" | \
  docker login --username AWS --password-stdin "${AWS_ACCOUNT_ID}.dkr.ecr.${AWS_REGION}.amazonaws.com"
cd ../..
docker build -t payments-service:demo .
docker tag payments-service:demo "${ECR_REPO}:demo"
docker push "${ECR_REPO}:demo"
```

6. Only **after a reachable Kafka endpoint, network rules, and Kafka auth are ready**, set `deploy_service=true` and the appropriate `kafka_bootstrap_servers` (and any required client security configuration), then run another `terraform plan` / `apply`. Example for a reachable TLS broker with no additional auth:

```bash
cd infra/terraform
terraform plan -var='deploy_service=true' \
  -var='kafka_bootstrap_servers=REPLACE_WITH_REACHABLE_BROKER:9094'
# If correct, repeat the same variables in terraform apply.
```

7. When finished **destroy resources** using `terraform destroy`. Validate that RDS, Fargate, ECR, logs, public IP, and other demo resources are gone. Separately delete anything you provisioned outside this Terraform configuration (such as MSK).

## Security and limitations

- Never commit credentials, `terraform.tfstate`, plans or `.tfvars` containing secrets. The repository `.gitignore` excludes these. Use a remote encrypted Terraform state and state locking for real teams.
- The AWS RDS password is generated by RDS and injected into the ECS container using Secrets Manager; Terraform does not set a plaintext database password. This demo uses the RDS **admin user** as its application user, which is **not production-grade**; create a least-privilege DB role before real use.
- ECS's public-IP route is intentionally simple; a production design uses private subnets, VPC endpoints/NAT, an authenticated ingress via ALB/API Gateway, TLS, WAF, image scanning/rollbacks and availability zoning.
- Fargate service has no ALB. You must discover the current ECS task public IP, optionally allow only your IP in `allowed_cidr` and use HTTP on port 8080 for this **non-sensitive demo**. Never expose this demo publicly with real customer data.
- RDS `skip_final_snapshot=true`, `backup_retention_period=0`, and ECR `force_delete=true` facilitate teardown **and destroy data**. Do not reuse these defaults for production.
- AWS charges can apply while idle: RDS, allocated storage, Secrets Manager, ECR storage, data transfer, public IPv4, CloudWatch, Fargate and any separately deployed Kafka service. Review current AWS pricing; no free-tier claim is made here.
